# RootLens · 五分钟演示路线

**要讲清的是：异构观察如何成为可核验的候选解释，再由人记录判断与维护知识。**
不是展示所有字段，也不是把模型输出说成已验证根因。对应论文 `RootLens_ChinaVis_2026 (2).pdf` §4–5。

## 演示前

打开 `/evidence`，选择 **Demo**。如需从头讲，点击“重置演示”并确认。
这个操作不清理 Backend 数据或 Replay 草稿。建议桌面宽度 1440px。

## 1. 证据浏览 · 约一分钟

选择“瓶体划痕 · 合成样本”，切换**原图 → 异常区域 → 响应图**，再试一次叠加。

讲述重点：视觉发现先成为 observation，统一证据保留对象、异常线索、置信度和来源，
而不是直接给出根因。点击“查看来源与字段”时再展开细节，不逐项念字段。

> 此图是可复现的受控合成样本。响应图是与无缺陷基准的像素差分，
> 不是 MVTec 原图或训练模型热力图；它用于演示检查方式，不是论文实验结果。

可短暂切换“过程故障案例”：显示已提供的变量贡献；没有原始序列就不画曲线。
由此说明不同模态采用同一证据入口，再回到划痕样本点击“查看关联分析”。

## 2. 关联分析 · 约两分钟

依次选择“机械接触”“搬运损伤”，观察中间路径随候选切换。
点击路径中的关系，右侧核验两件不同的事：

- **观察从哪里来**：图像或其他原始资源。
- **知识关系依据**：关系支持内容、来源说明及定位。

打开“查看原始出处”，展示实际来源文本和行号。
这里的 `manual_curation` 是人工整理的开发知识，明确不代表 MVTec 提供工厂根因标注。
**有解释路径不等于已验证因果。**

切换“人工审阅”，确认当前对象，填一个理由后“记录审阅”。
例如：“线状划痕与接触损伤相容，但缺少现场接触记录，仍需核验。”
再看“审阅记录”：新增的是判断记录，不是自动改写模型或候选排序。

## 3. 编辑知识草稿 · 约一分钟

选中路径关系，点击“编辑知识草稿”。修改关系或来源/支持内容，填写修改理由，
点击“预览修改”，检查前后对比，然后“保存草稿”。也可展示新增节点/关系、停用或撤销。

讲述重点：**人可以维护知识，但修改先进入有来源、有理由、可追踪的草稿。**
刷新后查看“已保存版本”；既有分析路径保持不变。Demo 保存在浏览器，Backend 追加到 PG，
均不会自动发布 Neo4j 或重新推理。

## 4. 知识维护 · 约一分钟

进入“知识维护”，打开一份来源说明，展示素材原文与抽取/构图记录的关联。
打开已有图谱记录的“来源与审阅”，左边选关系，右边只核对当前关系的依据、判断和理由。

以此补上知识侧的来路：来源素材形成可审阅关系，再服务于解释路径。
Demo 不执行真实抽取或构图；这些只在 Backend 运行。

## 避免这样讲

- 不把排序得分说成根因概率或正确率。
- 不把来源说明片段说成已经取得全部外部原始文档。
- 不把晶圆/视觉候选机制说成真实工厂 RCA 结论。
- 不把草稿保存说成已更新运行知识图谱。
- 不把构图只读快照中的 `RootCause` 节点说成当前案例的诊断。

切换 Backend 前确认 API 地址，旧 API 进程需正常重启才能加载本分支的新接口。
安装与启动遵循根 README；**不要为演示重建或重新初始化既有数据库**。
